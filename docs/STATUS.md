# GoreeCloud Maps — Status

**Stage:** Source development preview; not deployed or production accepted.

**Source present:** Web map client, Node proxy scaffold with optional Nominatim/OSRM adapters, bounded JSON POST request handling, local saved locations, local GeoJSON saved-place portability, manual route coordinate entry, provider consent and automation tests.

**Verified automated checks (November 6, 2026):** Node tests, syntax checks, Vite build and production-dependency advisory check passed in GitHub Actions. A separate real Chromium test job passed synthetic desktop (1440×900), tablet (820×1180) and phone (390×844) journeys for map consent and canvas startup, coordinate search, local saves, GeoJSON import/export, manual routes, mocked search/routing providers, theme persistence, and rejection of obsolete route results. Evidence: [main browser CI 42244215895](https://github.com/GoreeCloud/maps/actions/runs/42244215895) and [PR #7 browser CI 42244883746](https://github.com/GoreeCloud/maps/actions/runs/42244883746). The runs preserved synthetic screenshots for review; no human visual acceptance is claimed.

**Accessibility and visual review progress (November 6, 2026):** [PR #9](https://github.com/GoreeCloud/maps/pull/9) merged fixes for phone consent-card clipping, tab-switch scroll retention and map-label/control overlap; it added a keyboard-activated map-center pin. The [post-merge main browser workflow](https://github.com/GoreeCloud/maps/actions/runs/42294074235) passed the prior synthetic three-viewport scenarios and additional desktop/phone keyboard and forced-colors checks. Screenshots from [PR #9 passing branch run](https://github.com/GoreeCloud/maps/actions/runs/42293848035) were inspected for the reported phone defects, and the consent action/link, Saved heading and map controls appeared accessible in those cases. See [scoped QA review](UI-QA-2026-11-06.md) for evidence and limitations.

**Consent-first renderer performance (November 6, 2026):** [PR #11](https://github.com/GoreeCloud/maps/pull/11) merged dynamic MapLibre/worker loading after the user selects **Load interactive map**, with a pending-load invalidation guard when consent is withdrawn. [Branch Chromium CI](https://github.com/GoreeCloud/maps/actions/runs/42295292604) verified the renderer code chunk was absent before consent and fetched afterward, while existing map interactions still passed. Vite reported an initial JS chunk of 17.96 kB versus approximately 1,086 kB before the split (uncompressed sizes); the deferred renderer chunk was about 1,105 kB. These are build sizes, not measured user download speeds.

**OSMF tile policy correction (November 6, 2026):** The default community tile service requires valid web Referer headers. The app's former `no-referrer` response was incompatible; source now uses `strict-origin-when-cross-origin`, disclosing only the website origin to cross-site HTTPS tile requests (alongside IP and tile coordinates). See the [official OSMF tile usage policy](https://operations.osmfoundation.org/policies/tiles/). Production provider compliance and live network behavior still need verification.

**Still unverified:** real hardware geolocation and touch behavior, screen-reader accessibility, complete keyboard-only/contrast/zoom audits, comprehensive GoreeCloud UI design-token and human visual acceptance, live geocoder/router and tile-service compatibility, provider licensing at production scale, operational HTTPS/reverse proxy, trusted deployments and production monitoring. CI uses mocked geocoder/router responses and intercepted tiles, not evidence of production navigation accuracy.

**Dependency reproducibility (November 6, 2026):** `package-lock.json` v3 is committed, with 90 package entries and SHA-512 integrity records for 89 registry packages. Both GitHub workflows now install application dependencies with `npm ci`; Playwright remains a pinned ephemeral CI-only browser-test dependency. Initial lock creation used an isolated authorized development checkout and the production-dependency audit reported no findings. Repeat and verify these checks in the feature-branch and merged-main CI before treating clean installs as accepted.

**Unavailable in this milestone:** native Android/iOS, turn-by-turn navigation, traffic and crowd reports, elevation/3D, offline tile downloading, account sync and live business data.
